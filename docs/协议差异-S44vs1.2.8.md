# 雷达数据对比：S44 源码 vs 王者视界 1.2.8（现在服务器上跑的那套）

> 结论先行：**"自己方英雄数据"不是新版才传的，payload 里一直都有双方 10 个人。**
> 变的是前端解析：新版用英雄段第 10 个字段（`f[9]`）当"本机阵营基准"，把 5 个自己人单独识别出来（红色），
> S44 前端只读第 9 个字段（`f[8]`）当阵营号上蓝/红两色，压根不认"自己"。两版颜色语义是反的。

---

## 1. 两套是什么

| | S44 源码（老） | 王者视界 1.2.8（现在） |
| --- | --- | --- |
| 前端 | `S44王者纯净带卡密登录/index.html`（105 KB，明文 JS） | `dist/index/assets/index-MdrsxC1t.js`（557 KB，obfuscator 混淆） |
| 后端 | `home-server-0.0.1-SNAPSHOT.jar`（Java Netty，6 MB） | `king-vision-relay`（Go 静态编译，17 MB） |
| 登录 | PHP + MySQL 卡密（`api/login.php`） | 后台密码 / 授权码，无卡密表 |
| 客户端上报 | WebSocket 直连，`gameData[==]room[==]target[==]payload` | TCP 9999 裸流，同格式 |
| 浏览器订阅 | WS `/ws` | WS `/ws`（nginx 反代 8888） |
| 服务端对数据 | 纯转发，一个字段都不改 | 纯转发，一个字段都不改 |

两个 jar 是同一份：`home-server-0.0.1-SNAPSHOT.jar` 与 `网页源码/wz.jar` md5 完全相同
（`18967358b7c168087dcb5970ff932cd9`）。

所以**数据差异 100% 来自客户端上报版本和前端解析器**，不来自服务端。

## 2. payload 分段结构

```
gameData##<payload>
payload = 段0 --- 段1 --- 段2 --- 段3 --- 段4
         英雄    资源    小兵    防御塔   地图旋转
条目用 == 分隔，字段用 , 分隔
```

| 段 | S44 前端 | 新版前端 | 说明 |
| --- | --- | --- | --- |
| 0 英雄 | ✅ 读 | ✅ 读 | 字段含义不同，见下 |
| 1 资源/野怪 | ✅ 读 | ✅ 读 | `0,刷新秒,资源ID,x,y` 两版一致 |
| 2 小兵 | ❌ **完全不读** | ✅ 读 | 新版新增，`x,y,阵营` |
| 3 防御塔 | ✅ 读，按 `x,y,hp,zy,w,h` | ✅ 读，按 `id,curHp,maxHp,x,y,team,flag` | **字段布局不同，不兼容** |
| 4 地图旋转 | ✅ 读 | ✅ 读 | 一致 |

实测线上帧（`/d/tmp/relay/orig_rooms.json`）多数只有 3 段：英雄 / 资源 / 小兵，
段 3、段 4 经常是空的。新版解析入口写死 `if (parts.length < 3) return null`，S44 没有这个门槛。

## 4. 敌我判定：这才是真正的不一样

### 新版（`index-MdrsxC1t.js` 反混淆后）

```js
const refTeam = f[9]?.trim();          // 本机玩家阵营，整帧一个值

function Nl(team, ref) {               // 英雄敌我
  const a = team?.trim(), b = ref?.trim();
  if (!a && !b) return 'blue';
  const n1 = Number(a), n2 = Number(b);
  if (isFinite(n1) && isFinite(n2)) return n1 === n2 ? 'red' : 'blue';
  return (a || b) ? 'red' : 'blue';
}

// 英雄
team: Nl(f[8], f[9])        // f[8]==f[9] → red（我方），不等 → blue（敌方）
// 小兵
team: Bl(f[2], refTeam)     // 同队 → red，异队 → blue
// 防御塔
team: Wl(f[5])              // 1 → blue，2 → red
```

渲染层（小地图）也是按这个分：`team==='red'` 画实心方块，`team==='blue'` 画圆点。
所以新版页面上**红色 = 自己队**，蓝色 = 对面。

### S44（明文）

```js
var zy = Number(rw[8]);        // 只读第 9 个字段
if (isNaN(zy)) zy = 0;         // 默认红方
drawImageAtPosition(rw[5], rw[6], images[rw[0]], 40, 40, zy, 1, ultCD, skillCD, ...);
drawHP(rw[5], rw[6], rw[7], zy);
```

```js
// 血条 / 防御塔颜色
var hpColor = (zy === 1 || zy === '1') ? 蓝方血条颜色 : 红方血条颜色;
```

S44 **只认 f[8]**：1 → 蓝，其他 → 红。它把 f[9] 拿去当召唤师技能 CD 用，
所以页面上看到的是"蓝方/红方"，不是"我方/敌方"。

S44 那个「显示我方 / 不显示我方」按钮（`showThisFunction`）只改了按钮文字，
`showThisData` 变量在绘制路径里一次都没被引用 —— **空按钮，不生效**。

### 结论对照

| | S44 | 新版 |
| --- | --- | --- |
| 数据里有几方 | 双方全在（f[8] 有 1 有 2） | 双方全在（同左） |
| 是否区分"自己" | 否 | 是（f[8] vs f[9]） |
| 红色代表 | f[8]≠1 的英雄（可能是敌方，也可能是自己） | 自己队 |
| 蓝色代表 | f[8]=1 的英雄 | 对面 |
| 能否只看敌方 | 不能（按钮是死的） | 改一行就行 |

## 5. 实测证据

线上抓的 4 个真实房间（每帧 6~10 人，`f[9]` 每帧只有一个值）：

| 房间 | 英雄数 | f[9] | f[8]=1（敌方） | f[8]=2（我方） |
| --- | --- | --- | --- | --- |
| 492 | 10 | 2 | 5 | 5 |
| 603 | 6 | 2 | 4 | 2 |
| 868 | 8 | **1** | 5 | 3 |
| 965 | 10 | 2 | 5 | 5 |

房间 868 的 f[9]=1，说明那一局本机玩家在 1 队 —— 基准值是跟着玩家走的，不是写死的。
`f[13]=1` 的那几条是 ID 620/621（训练营假人，坐标 3265,-2971），新版判成 `isAI`。

## 6. 你看到的"传了自己方数据"到底是什么

1. **数据层面**：客户端上报的 payload 一直是整图全量（10 人 + 小兵 + 资源），从 S44 时代就这样。
   jar 和 relay 都只做 `gameData##` 原样转发，不裁剪、不过滤。
2. **呈现层面**：新版前端第一次把"自己队"标出来了 —— 小地图上自己队是方块、对面是圆点，
   英雄情报计数按双方合计算（`N / 10`），所以看起来"多了 5 个人"。
3. **风险层面**：自己方 5 人的实时坐标确实在 payload 里明文传，任何订阅了房间号的人都能看到。
   这是协议设计，不是新版偷偷加的。

## 7. 想只显示敌方怎么改

新版前端反混淆后，改解析入口一处即可（`heroes` 过滤）：

```js
// 原始
team: Nl(f[8], f[9])

// 只保留敌方（对面 = blue）
const t = Nl(f[8], f[9]);
if (t === 'blue') {
  heroes.push({ id, ultimate, skill, x, y, hp, team: t, isAI, isReturning });
}
```

小兵同理，`Bl(f[2], refTeam)` 只留 `'blue'`。
但注意：前端是混淆压缩产物，改完要重新打包；服务端（relay）侧过滤更省事 ——
在 relay 转发 `gameData` 前按 `---` / `==` / `,` 切一刀，把 `f[8]===f[9]` 的条目丢掉。
服务端改一次，所有客户端都生效，不用重发前端。

## 8. 附：两套的字段错位风险

如果拿 S44 那套前端去接现在的客户端上报：

- 防御塔段会错位：S44 按 `x,y,hp,zy,w,h` 读，新 payload 是 `id,hp,maxhp,x,y,team,flag`
  → 塔的位置会画到 (id, hp) 上，基本全乱。
- 召唤师技能 CD 会显示成 `6878` 这种血量数字（S44 把 f[1]/f[2] 当 CD 读）。
- 小兵段（parts[2]）完全不显示。

反过来，新版前端接 S44 老客户端的 payload：防御塔读不到（id 不在 1690~1699），小兵段为空，英雄正常。
